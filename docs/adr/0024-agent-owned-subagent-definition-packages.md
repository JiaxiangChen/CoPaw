# Agent-owned SubAgent Definition Packages

**Status:** Accepted. Reusable SubAgent Definitions have three explicit sources: fixed built-ins, Skill-owned packages, and Agent-owned packages. Agent-owned packages are managed only through the current Agent Profile's expert center at `workspaces/<agent-id>/agents/<definition-id>.toml`; the filename is a stable opaque management identity and the TOML `name` remains the editable exact runtime name. This separates reusable-expert authoring from Main Agent delegation and makes agent-local ownership unambiguous.

The Main Agent no longer receives a registration tool. It receives a turn-start directory of enabled Definitions' names, descriptions, and trigger keywords, selects only by exact name, and may still supply an instruction for an unknown-name one-off run. Creation, saving, enablement, disablement, and deletion are distinct actions; catalog changes apply only on a later Main Agent turn, while launched runs retain their snapshots. The expert center displays only Agent-owned packages, uses a structured form and generated TOML preview, and protects mutations with revision matching. Skill-owned and built-in Definitions remain outside that page and keep their respective lifecycles.

Agent-owned packages use the same bounded capability semantics as Skill-owned packages: parent-enabled built-in tools are inherited by default; only explicitly listed, parent-enabled MCP clients are available, and an empty or omitted MCP list grants none; optional Skills load only from parent-enabled Skills; unavailable dependencies are retained in configuration but silently omitted at launch. A configured but unavailable model falls back to the parent model. These choices preserve a user-configurable expert catalog without allowing an expert to expand the parent Agent's permissions or mutate a queued run's configuration.
