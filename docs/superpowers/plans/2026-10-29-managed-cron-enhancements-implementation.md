# 新版定时任务四项优化实施计划

**Goal:** 按已确认设计完成年份、日期段、整组暂停、前批优先和加急重跑及其界面。

**Architecture:** 三服务共库；复用现有管理操作及派发容量控制；日期维护仅由外部平台调用，不新增内部定时器。

**Spec:** `docs/plans/2026-10-29-001-feat-managed-cron-enhancements-plan.md`。

## 执行约束

- 当前 `codex/cron-task-tracking` worktree，主线程顺序实现，不派发代理。
- 测试先失败、实现后验证；不自动提交、推送或执行业务 DDL。
- 旧接口/页面语义不变；任务、会话和平台绑定身份不变。
- 年份和日期均为空时兼容原任务；后批可使用剩余容量，不等待前批结束。
- Python 函数复杂度不超过 15，中文注释；前端沿用现有组件与样式。

## 单元及验收

### U1：日期状态与持久化字段

- 范围：Scheduler 定义、查询、状态和投影，SWE 实际开始门禁。
- 先验证：`test_managed_cron_date_state.py` 的不限日期、包含首尾日、未生效/已过期、人工暂停保护；SWE 开始边界。
- 成功标准：共库读取一致，日期限制不重写人工意图，已开始任务不被中断。

### U2：Cron 年份

- 范围：Scheduler 新链路语法、平台注册、分发散列、未来时间和 SWE 新模型。
- 先验证：`test_managed_cron_year.py` 的五个精确平台值、非法年、期限耗尽；旧模型仍拒绝六段。
- 命令：WSL 项目虚拟环境运行 Scheduler 年份及原管理/查询测试，再运行 SWE managed 资源/执行/通知测试。
- 成功标准：年份在全链路保留，五段回归不变，不修改 croniter 安装包。

### U3：整组异步暂停

- 范围：pause 路由、冻结子任务、数据库暂停、水位、异步平台同步和失败续办。
- 先验证：真实 SQLite 管理事务的父子暂停、子任务范围、batch_paused、accepted 跳过及 running 保留。
- 成功标准：入参及 operation 响应与删除一致，先本地停再后台关平台，不误停兄弟任务。

### U4：日期配置和同步维护

- 范围：创建缺省、整组继承、独立修改、无用户 Header 的来源维护入口、即时执行门禁。
- 先验证：创建不传/null 不限；父改子同步；子拒绝改；清空后解除平台暂停；失败留待下一次外部调用；没有内部日期 lane。
- 成功标准：同步返回当次结果，不新增调用幂等、抢占、续办、历史追赶或业务补跑。

### U5：跨批优先和加急

- 范围：work_query 排序、重跑通道、同次投递恢复、当前模型池容量保护。
- 先验证：前批顺位低的成员仍优先于后批顺位高的成员；A 6 个运行/容量 10 时 B 可用 4 个名额；延期重试不预留空间；urgent 仍守并发与日期。
- 成功标准：不增加整批完成屏障；原批关联、业务次数及 is_final 不变。

### U6：前端及最终核验

- 范围：新版 API/types、任务列/编辑器/子列表、日期修改、整组暂停、年份回显、追踪属性。
- 先验证：Vitest 列表区间/不限、父修改/清空及子只读、正确新路由；TypeScript、lint、构建。
- 浏览器：原布局、1440/1280 下区间显示及修改，父子继承，年份不回退为 09:00。
- 最终：Scheduler 全目录、SWE managed 范围、前端相关回归，复杂度/格式/差异检查。独立评审未运行，主线程自检须如实标记。
