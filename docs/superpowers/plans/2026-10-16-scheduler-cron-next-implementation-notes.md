## 必须补齐的执行收尾

当前执行核心已经落了稳定执行身份、快照、SWE 直接写结果、运行围栏和去重，但临时结果提交失败后的持久恢复仍须接通。不能只在进程里记住结果，也不能通过重新运行 Agent/Workflow 来补一次结果。

可利用原有会话/产物存储保存待提交结果凭证，数据库恢复后只按同一 execution_id 补交结果；它不是 jobs.json 或旧展示缓存，不作为任务查询的权威数据。后台需要先尝试补交已经产生的结果，再将超过运行期限且确实无法恢复的登记收敛为结果未确认的错误。普通执行异常和真正管理步骤失败均不因此获得自动重跑业务的权限。

运行队列需要保存独立的 not_before_at：批入口提前收到一组工作后，各条执行等到自己的已冻结时间再派发。scheduled_fire_at 表示逻辑执行期，用于普通/批跨入口去重，不能同时拿它代替条目最早派发时间。普通任务仍只处理平台已经触发的工作，不扫描定义补生到期事件。

执行收尾还需补两个真实竞争场景：第一，定义版本只是参数快照标识，不能代替执行身份和实际运行顺序；较早执行不能覆盖较新结果，但合法旧快照的成功结果仍需按已读水位正常统计，不能仅因内容更新就吞掉未读。应使用共库状态行分配的实际启动顺序归约最近结果，并把现有仅手工修改版本/预览的测试加强为两个真实在途执行的竞争测试。第二，停用后又恢复，停用时尚未开始的旧队列仍应跳过，不能因为恢复时 enabled=true 又继续启动。可由共用状态版本分配停用/自动暂停的队列失效水位，在执行登记中保存入队水位；不使用跨实例墙钟判定事件先后。模式切换不写该失效水位，保留已入队继续的规则。

自动未读暂停还需保留已有手动暂停原因及首次自动暂停时间，不能被后续在途结果覆盖。SWE 记录自动暂停事实和必要失效边界，Scheduler 处理定义启停、兼容投影和平台效果；用户恢复后，旧自动暂停处理不能再次停用任务。

## 分发与旧存量隔离

已经核对旧 SWE 的 broadcast_task_store.py：旧代码使用 swe_cron_broadcast_tasks 和 swe_cron_broadcast_task_items。不能直接把新版记录写进去再让旧后台误领。

新版采用独立表，例如 swe_cron_managed_broadcast_tasks、swe_cron_managed_broadcast_items；最终表名和列随人工 SQL 一并交付，不修改旧分发表或旧领取规则。执行登记已经采用独立新表，同理禁止新旧队列互领。

异步分发先持久化源快照、目标、保留/预留子任务 ID、预计子定义版本和偏移，再返回 202。实例恢复使用原轮记录，不重新选择 ID 或散列；真正目标失败通过明确新一轮处理，不提供旧轮失败项续办接口。

普通根任务创建仍禁止普通用户跨工作区创建。分发必须有私有的、经过共库分发记录核验的源授权路径，不能伪造 manager 或把真实操作人换成接收人。子任务定义的拥有者是接收方，管理操作 actor 仍是原发起人；源子关系写完整 tenant/source/Agent/job 四元组。

新一轮遇到失败的既有创建/更新，应复用有效 Chat 和已知平台绑定，并隔离旧操作；平台注册结果不明时仍不能盲目再次新增。已删除的对象只有明确新轮可以预留新 ID，旧轮迟到处理不能复活或另建替代任务。

0 人模式固定全部未删除子任务的稳定顺序和版本，仅调整排程/偏移；包括停用对象但不恢复启用，不覆盖正文/模型/技能，不创建资源。Cron 平移算法沿用现有 SWE 纯函数及回退行为，可在独立 Scheduler 包中保留同算法并用参数化测试核对，不引入 SWE 运行时依赖。

## 模式和批入口协调

同源分发与整组模式切换以数据库协调，不能让晚到目标恢复旧模式；允许技术上的操作互斥。源内容更新/源删除必须在事务里检查活动分发，拒绝时不先打删除标记。

三态的目标、配置版本、每项实际模式和平台同步进度分别存储。外部失败不得改为整组触发禁用；只有明确业务暂停、停用或删除等规则生效。进行中的切换不能换另一个目标，失败支持原操作人工重试。

切普通时先逐对象准备普通绑定并持久保存，再启用；成功对象用普通入口，尚未切换对象仍可由保留的批入口触发。确认所有对象都切换后才关闭组批入口，避免部分失败让旧方式对象一起断流。已经受理的批队列不因当前三态改变而取消。

切批模式时，单个任务自身 enabled 不决定组批入口的启停。组批入口、普通绑定、每项生效模式均先记录事实再启停；新批子任务不各自注册批入口。改变散列只调整必要批入口时间，不打开 batch_paused。

批入口提前量根据全部有效子任务实际偏移计算，不能只看本轮 targets 或请求窗口。保留未选历史子任务，Cron 回退的实际偏移为 0；通知和逻辑执行期都使用实际应用值。

专用路径为 POST /api/scheduler/cron/jobs/{job_id}/broadcast/children/batch-delete，合同详见 integrations/zhituo-scheduler-cron-api-v1.md 的 6.3。它仍是已经批准的选择子任务批量删除能力，不扩大范围；相较现有 children/actions 包装，还需整批目标清单和请求内容幂等、与同源分发互斥、区分已逻辑删除计数和清理结果。可复用管理日志，不新增异步批量 task 查询接口。桌面对外版的裁剪不表示取消目标中明确要求的三态能力。

该专用接口现在复用 swe_cron_registration_journal 保存 action=batch_delete 的整批清单和逐项结果，不新增异步删除任务表。父协调日志不修改父定义/状态，处理结束释放同源互斥；同请求重提只读取已处理子操作的新进度，失败清理不会因此自动重试。存储中断后的未处理项仍使用原清单和子操作 ID 同步续办；通用 retry 拒绝整批协调日志，要求重提原批量请求。

## 下一处装配前必须处理的容量边界

ManagedRecoveryWorker 已挂到实际 FastAPI 生命周期，使用 ManagedCapacityGate 原子领取。先只读校验实际字段，在旧循环启动前启用合并容量统计；退出先收拢工作再关闭连接。limit 仍只是每轮查询上限，不等于完整公平性或动态容量策略验收完成。

capacity_claim.available_capacity 已在新后台结构就绪后合并统计新旧在途占位；新记录仍不能让旧处理器领取。已复用既有 scope 租约、策略与容量快照，普通任务仍由外部平台给出时间触发，不新增定义到期扫描。新表全部就绪后即启用合并统计，即使后续客户端配置失败也不能忽略已经存在的新占位。

迟到 RPC 的围栏现已落地：SWE execute Body 增加 Scheduler 自动携带的 dispatch_token，首次受理在同一事务核对 dispatching 状态、当前占位持有者及期限。已退回 queued、已释放/转移或已过期的旧请求返回 409，且不初始化工作区；5 项实际 HTTP→共库测试已覆盖。已受理/运行的重复请求仍复用同次执行。recover Body 仍只有 execution_id/job_id，不重跑业务；dispatch_token 不是必配认证密钥。

执行登记现已冻结 provider_id/model_id，普通模型取持久定义的 model_slot 或 default 池，Workflow 以已发布绑定版本为准，不信任传输元数据自报模型。原子占位、过期接管及启动已装配；accepted 重投不重复占位，同任务并发限制防止等待周期占满池。内部合并统计不是新增运维配置，无新结构的旧部署不访问新表。

自动暂停、旧动作围栏、新页面、Chat 双来源，以及动态反馈/异步收敛已接通。接下来优先核对更新期间回调回执、平台绑定冲突和真实展示/执行上下文，再集中整理最终 SQL；不修改原执行历史结构，不让应用自动执行新 DDL。

当前领取先锁模型 scope，再建立事务内非锁定读视图、锁任务定义及执行，避免可重复读过早快照。旧 scope 租约/容量快照继续北京时间，新执行期限使用 UTC；已有测试验证时区及真实旧策略方法接入。过期接管排除自身，accepted 恢复不申请第二槽位。

## 后续实现优先测试

- 基本公平性已落地：ManagedWorkQuery 只读已有工作，按模型 scope keyset 轮转，在限量前排除同任务并发已满的周期；一轮每池只解析一次策略，逐条事务重核。已测试热池满额不阻塞另一池、并发已满不挡其他任务、满池恢复 accepted、错池凭证拒绝，以及坏策略不影响其他池。游标仅是操作轮转位置，不是任务权威缓存。
- 冻结优先级已实现：在同一受理事务中集合查询原历史的已读成功热度，复用旧 compute_batch_dispatch_order（用户/分行、热度、due、tenant/job），保存 dispatch_order，再以数据库 queue_order 稳定读取；不重排已有工作。新增字段仅在新运行登记表，热度读取原历史已有 async_status，不改原历史结构。queue_order 的人工升级需唯一自增索引，旧开发草案不能仅 CREATE IF NOT EXISTS。
- 动态反馈与子任务已实现：ExecutionSettlement 按主结果及原历史 async_status 记录 Scheduler 专用 settled_* 字段，不覆盖 SWE status/finished_at，不写 Monitor async_status。主成功且异步未结束继续占池、约束同任务并发并延后资源清理；双实例仅提交一次，错关联历史保留占位，坏行通过轮转不饿死后续工作。
- 已按旧终态事实接入统一统计：ManagedCapacityFeedback 将新 scope/反馈合并到原 CronSchedulingService 的唯一容量循环，旧 intents/events 的算法不变；不另起第二个调整器，不互领新旧队列。新统计只用共库已确认终态，失败时不发布半份容量，取消/失败收拢并行读取。新增三个列及索引的手工 SQL 已补入 execution-api 文档，U8 仍需集中核对与实际 MySQL 验证。
- 回调边界已补：更新中的合法活动引用保存 skipped，发布后重放不补触发；三态部分失败与分发批入口响应丢失不全组禁触发。未知 ID、无计划、跨 source、失效 pending 引用仍拒绝。已用实际管理/分发/模式服务与测试数据库走回调链，未把外部模拟边界当真实平台验收。
- 自动暂停已实现：AutoPauseController 以同一成功执行及暂停水位作私有授权，只读该事实再复用控制日志；不冒充源创建人/manager。定义及投影先停用，再同步普通入口，批源不关组入口；失败不自动续办，用户恢复可替代已失败旧动作，删除也可接管失败日志。中断只恢复原平台步骤，不重跑执行、不重增未读；两表相关时间列必须按最终 SQL 的 DATETIME(6) 保持同一事实精度。
