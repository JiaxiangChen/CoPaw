# 智拓定时任务：文件与内存兼容方案取消说明

修订日期：2026-10-15。状态：原兼容写入方案取消；第二阶段业务能力尚未实现。

## 当前决定

Scheduler 创建的任务（含分发子任务）以数据库为权威来源，不补写、更新或删除 `jobs.json` 中的兼容记录，也不向 SWE 旧任务内存 `_states` 写入展示投影。不开发 LegacyJobsFileWriter、旧内存适配层、兼容刷新接口或相应开关、重试和版本流水。

“新任务”按管理归属区分，不按创建日期区分。第一阶段仅导入数据库的 legacy 任务仍属存量，不自动接管；存量文件、内存、管理接口和执行通道不动。

## 执行与查询

- 新任务普通调度也使用 Scheduler 新普通入口；新批任务使用新批入口，二者均调用 SWE 新快照执行通道。
- 新任务查询从数据库取得定义和状态，不依赖旧 SWE 列表、详情或状态接口，也不新增旧查询查库补偿。
- Chat 前端通过额外的新列表请求合并新旧任务，报告预览的标记已读按归属分流；这是前端接口适配，不是恢复文件或旧内存投影。详见第二阶段最新边界。
- Scheduler 保存管理字段；SWE 直接保存实际运行状态、结果、摘要和未读等必要事实，不通过 HTTP 复制同一份数据库状态。
- 必要的执行信号量、锁、请求上下文和在途对象不属于被取消的旧状态投影，仍需保留。Chat、会话及其他执行产物也不在本次全量文件迁移范围内。
- 取消只针对文件和旧内存，原先确认的新任务 `swe_cron_jobs` 数据库兼容投影暂时保留，不修改旧路径既有写入逻辑。

## 更新与存量边界

更新期间暂缓接收新触发，已入队和执行中的任务按原快照继续。准备及平台同步确认完成后，新版本才生效；失败保留待处理状态并允许重试，不能自动恢复调度。期间到达并被暂缓受理的触发不补跑，记录原因；完成后等待生效排程的下一次正常触发。

本文件替代原有“数据库提交后再异步投影到文件和本机内存”的方案，不应继续按 Git 历史中的适配层设计开发。
