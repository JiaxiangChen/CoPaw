# 智拓经 Scheduler 删除定时任务流程

日期：2026-10-14

开发基线：`v1.0.0`

状态：逻辑删除、平台停用和 SWE 资源清理核心已实现，逐次执行登记和正常延迟清理收尾仍待接入；见[管理接口开发记录](2026-10-16-scheduler-cron-management-api.md)。

修订：2026-10-15，按[第二阶段最新边界](2026-10-15-zhituo-scheduler-cron-phase2-boundaries.md)取消文件、旧内存投影；Scheduler 新任务的普通与批调度均使用新版入口。

关联设计：[智拓经 Scheduler 创建定时任务流程](2026-10-14-zhituo-scheduler-cron-create-flow.md)

智拓保留现有删除触发条件和任务选择逻辑，将直接调用 SWE 定时任务删除方法改为调用 Scheduler HTTP 接口。Scheduler 负责数据库删除状态、阻止后续调度及平台定时器清理；SWE 负责必要的任务执行资源清理。

本次可以认为没有存量智拓任务。删除接口只处理新流程创建并进入数据库的任务，不增加旧任务迁移或文件查找兜底。

## 已确认的范围

- 删除整个规划时，智拓按现有业务逻辑选出各场景的源任务和相关分发子任务。
- 修改规划并移除场景时，智拓按现有业务逻辑选出被移除场景的源任务和子任务。
- 将 `mgr.delete_job()` 和 `target_mgr.delete_job()` 等任务删除方法调用替换为 Scheduler HTTP 调用。
- Scheduler 的删除接口一次删除明确指定的一个任务。子任务由智拓选出并逐个调用删除接口，不由 Scheduler 自动级联枚举和删除。
- 不顺带调整规划删除权限、发布中禁止删除的规则、分发子任务选择范围或历史数据清理策略。
- 不删除其他规划、用户的全部定时任务或其他无关任务。

任务查询和选择能力的其他迁移不包含在本次删除接口设计内。接口本身以数据库判断任务存在和删除状态，不依赖兼容文件。

## 三个应用的职责

| 应用 | 负责 | 不负责 |
| --- | --- | --- |
| 智拓 | 保留规划删除及移除场景的业务规则；选出任务；逐个请求 Scheduler 删除；根据结果处理自己的规划数据 | 不直接调用 SWE 的 CronManager 删除方法，不承担任务表和平台定时器清理 |
| Scheduler | 校验任务归属及权限；逻辑删除任务和兼容投影；阻止后续执行派发；清理该任务的定时器；调用 SWE 清理接口；记录进度并返回结果 | 不删除财富规划数据，不自动扫描分发对象或级联删除其他子任务 |
| SWE | 清理原有删除逻辑负责的关联任务 Chat 等执行资源；已开始的执行仍保存自身运行结果 | 清理接口不写任务逻辑删除和管理进度，不再次停用平台或调用 Monitor 同步删除，不通过执行收尾恢复任务 |

SWE、Monitor、Scheduler 使用同一个数据库。新任务的数据库删除状态由 Scheduler 维护，不需要经 SWE 或 Monitor HTTP 接口复制同一删除状态。

## 删除流程

### 1 智拓提交指定任务的删除请求

智拓在已有规划删除或场景移除流程中选出任务，将任务 ID、scope、Agent 等身份提交 Scheduler。源任务和子任务使用各自真实的身份，不能以同一工作区身份批量误删。

智拓对规划数据的处理沿用原业务流程，不由 Scheduler 接管。Scheduler 单任务接口也不把一次请求解释为“删除整个规划及全部子任务”。

### 2 Scheduler 校验任务身份和权限

Scheduler 从数据库定位任务，校验调用方是否有权删除该任务。任务 ID 必须结合工作区、Agent 身份使用，防止跨租户或跨工作区删除。

| 数据库中的情况 | 接口行为 |
| --- | --- |
| 任务存在且未删除 | 执行删除流程 |
| 该任务作为源任务仍有排队或处理中的分发 | 拒绝此次删除，返回分发进度，等待结束后重试；不写删除标记，不清理资源 |
| 任务已标记删除 | 幂等返回删除状态，并继续处理未完成的清理 |
| 任务从未存在 | 返回 `404`，不当作已删除成功 |
| 身份或权限不符合 | 拒绝操作，不修改数据 |

没有存量智拓任务，不查旧表或 `jobs.json` 来兜底确认一个新表中不存在的任务。旧表仅承担新任务的兼容投影。

源任务的进行中分发检查与删除、分发受理在数据库内协调，防止校验后并发创建子任务。该限制针对作为分发源的任务，不扩展为所有接收方子任务禁止单独删除，也不改变不自动级联的规则。

### 3 Scheduler 先逻辑删除并阻止后续派发

在数据库事务中完成：

- 将 `swe_cron_jobs_v2` 标记为已删除并禁用。
- 在 `swe_cron_job_states` 记录删除进度和待清理事项。
- 将 `swe_cron_jobs` 兼容投影标记为已删除、禁用。

新任务的回调和派发入口按数据库删除状态阻止新执行，不查文件或内存兜底，也不因资源清理未完成恢复任务。

先逻辑删除，不立即物理删除任务定义和状态记录。清理所需的外部调度 ID、Chat ID、会话绑定和任务版本应保留，以便后续处理和失败重试。

### 4 Scheduler 清理该任务的外部定时器

Scheduler 根据数据库中的绑定调用平台：

- 普通任务有外部定时器时，停止该定时器。
- 指定任务有独立批父任务定时器时，也停止属于该任务的批定时器。
- 批子任务没有独立定时器时，不虚构或新建平台清理对象。

平台清理保持现有语义：将名称加上“已删除”标记并停止调度，不强制改为物理删除平台记录。

这里处理的是指定任务自己的平台绑定，不代替智拓选择和删除全部分发子任务。平台失败时记录清理未完成及错误，允许重试；数据库中的逻辑删除状态不撤销，也不能将失败表述为平台已经清理完成。

外部操作进度可以在现有任务状态和操作日志设计中承载，具体字段及是否复用 `swe_cron_registration_journal` 待细化，不预先新增独立删除日志表。

### 5 Scheduler 调用 SWE 任务资源清理接口

Scheduler 将任务身份和数据库保存的执行资源绑定交给 SWE。SWE 清理原有删除逻辑负责清理的关联任务 Chat 等资源，不扩展到执行历史、用户其他会话或其他任务。

清理应能重复调用：已经清理的资源不应导致第二次删除失败。对要清理的资源仍需核对任务、用户和工作区归属，不能仅凭客户端传入的 Chat ID 删除任意资源。

不能直接调用旧 `CronManager.delete_job()`，因为该方法还会操作外部平台、文件和 Monitor，造成重复处理。资源清理应独立封装，失败及是否尚待重试与任务已逻辑删除的事实分别记录。

### 6 Scheduler 返回删除及清理状态

返回结果应区分两个事实：任务已经逻辑删除，以及平台、SWE 执行资源是否已经清理完成。不能仅用 `deleted: true` 暗示所有外部清理均已完成。

已确认平台停用或 SWE 资源清理失败后由用户人工续办，不新增自动后台失败重试。管理页保留“已删除、清理未完成”的可查可重试记录，重试复用原删除操作及绑定，只继续未完成步骤。不得因为普通列表排除了已删除任务而令授权用户失去重试入口，也不得因重试恢复任务为可执行状态。

本流程没有文件或旧内存投影清理步骤。具体响应字段和清理状态名称在接口契约设计时确定。

## 数据库和执行资源处理顺序

| 阶段 | 处理方 | 对象和操作 |
| --- | --- | --- |
| 提交请求 | 智拓 | 指定单个源任务或子任务的身份 |
| 确认逻辑删除 | Scheduler | 更新 `swe_cron_jobs_v2`、`swe_cron_job_states` 和 `swe_cron_jobs` 兼容投影 |
| 阻止后续执行 | Scheduler | 回调和派发入口以数据库删除状态为准 |
| 清理平台绑定 | Scheduler | 停止该任务的普通或批父定时器，保存清理进度和错误 |
| 清理执行资源 | SWE | 清理关联任务 Chat 等原有范围内的资源，返回清理结果 |
| 返回调用结果 | Scheduler | 区分已逻辑删除和外部清理是否完成 |
| 处理规划数据 | 智拓 | 按原业务流程及调用结果处理自己的规划、场景和分发对象数据 |

状态表名称使用 `swe_cron_job_states`，不加 `v2`。任务定义和状态记录不在请求开始时物理删除；最终物理清理或保留期限不属于本次范围。

## 创建删除交错及晚到操作

新路径没有兼容文件或旧内存投影，删除并发控制集中在数据库、平台操作和执行资源上。

晚到的创建准备或平台注册结果不能将已删除任务恢复为就绪；必要的外部清理信息仍需留下。晚到的执行结果不能清除删除标记或将旧表投影恢复为启用。具体并发控制、版本校验和结果记录方式在实现前细化。

删除管理状态由 Scheduler 写，执行状态仍由 SWE 按执行身份写入共库。已开始的执行可以保留完成结果，但不能重新插入已清理的任务状态记录、清除删除标记。未开始的已删除任务不再派发；在途执行所需资源延后清理，不因清理接口提前销毁。统一约束见 [执行状态写入分工](2026-10-14-zhituo-scheduler-cron-execution-entry-flow.md#执行状态写入分工与并发约束)。

## 失败和幂等边界

| 情况 | 处理边界 |
| --- | --- |
| 重复删除已标记删除的任务 | 幂等返回，并继续尚未完成的清理 |
| 从未存在的任务 | 返回 `404`，没有旧任务或文件兜底 |
| 数据库逻辑删除失败 | 不宣告任务已删除，不将文件删除当作数据库成功的替代 |
| 平台停用失败 | 保留任务不可执行状态，记录待清理和错误，允许重试 |
| SWE 资源清理失败 | 不恢复任务，明确资源清理尚未完成 |
| 不存在独立平台或 Chat 绑定 | 跳过对应清理步骤，不影响合法任务的删除 |

各系统之间没有统一事务。任务逻辑删除和外部清理完成是不同阶段，不以某一个资源清理成功代替整条流程成功。

## 尚需细化的内容

- Scheduler 删除接口、SWE 资源清理接口的路径、鉴权及请求响应字段。
- `swe_cron_job_states` 的删除进度、资源清理结果、错误和重试字段。
- 外部平台操作日志如何保存删除进度，包括是否复用注册日志。
- 任务版本、删除标记与晚到创建、平台注册、执行回写之间的并发控制。
- SWE 资源清理的接口组织方式、具体等待和重试策略。
- 已开始的执行继续完成，未开始的已删除任务不再派发；在途资源的引用识别、延后清理和完成结果保留的具体实现需要细化。
- 智拓如何呈现“已逻辑删除但清理未完成”；不据此扩大规划业务规则和子任务选择范围。

## 当前代码参考

- `console/src/pages/WealthWorkbench/api.ts`：当前规划移除请求。
- `src/swe/app/wealth_plans/router.py`：删除规划及更新时移除场景的入口。
- `src/swe/app/wealth_plans/publish.py`：当前源任务和子任务的选择、删除方法调用。
- `src/swe/app/crons/manager.py`：当前平台停用、文件删除、内存和 Chat 清理、Monitor 同步。
- `src/swe/app/crons/scheduler_adapter.py`：当前平台“已删除”改名并停止的语义。

总顺序：智拓选出任务 → Scheduler 校验单任务 → 数据库逻辑删除并阻止派发 → 清理平台定时器 → 调用 SWE 清理任务资源 → 返回删除及清理状态。
