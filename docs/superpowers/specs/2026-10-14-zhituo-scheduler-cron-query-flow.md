智拓通过 Scheduler 查询单个任务及源任务关联的子任务，以完成修改前读取、版本校验、处理进度确认及删除对象选择，不再调用 SWE 的内部任务读取函数。

两个接口只读数据库。不读取 `jobs.json`，不调用 SWE 准备执行资源，不注册或启停平台，不写兼容文件，也不通过读取触发任务修复。

本次没有存量智拓任务，不增加旧任务文件或旧表查询兜底。数据库是新任务的权威来源。

## 接口清单

| 方法和路径 | 用途 |
| --- | --- |
| `GET /api/scheduler/cron/jobs/{job_id}` | 查询指定任务的定义、版本、状态、绑定及必要处理进度 |
| `GET /api/scheduler/cron/jobs/{job_id}/broadcast/children` | 查询指定源任务关联的子任务，供智拓选择和展示 |

路径和以下字段表达目标契约，具体类型、错误码、分页默认值和完整响应模型在实现前细化。

## 三个应用的职责

| 应用 | 职责 |
| --- | --- |
| 智拓 | 提交明确任务身份，读取定义版本和处理结果；根据原业务规则过滤并选择子任务，逐个调用删除接口 |
| Scheduler | 校验权限及任务身份，从数据库查询定义和状态，返回脱敏结果和正确的分页信息 |
| SWE | 不参与这两个查询接口；Chat 和会话绑定使用 Scheduler 已保存的准备结果，不因读取再次准备或修复 |

智拓的规划列表、客户名单、场景技能等业务查询不迁入这两个接口。第二阶段为新管理页和 Chat 另补合法 scope/Agent 范围内的 Scheduler 管理任务列表，不借此增加跨用户全部任务或执行历史查询。

## 单个任务详情接口

### 入参

```text
GET /api/scheduler/cron/jobs/{job_id}
    ?scope_id=<任务工作区>&agent_id=<任务Agent>
```

- `job_id`：源任务或子任务的任务 ID。
- `scope_id`：该任务所属工作区身份。
- `agent_id`：该任务所属 Agent。

任务 ID 必须与工作区、Agent 身份结合使用，不能只按全库同名任务 ID 取第一条。参数中的身份不能替代可信请求上下文的权限校验。

### 返回内容

| 内容 | 用途 |
| --- | --- |
| 任务身份 | `job_id`、tenant、source、scope、Agent，确认操作对象 |
| 完整任务定义 | 名称、类型、执行内容、技能、排程、时区、允许查询的执行配置及业务关联 |
| `definition_version` | 智拓更新前读取当前版本，用于更新请求的并发校验 |
| 启用和删除状态 | 区分可执行、暂停及已逻辑删除任务 |
| 创建、更新、删除及平台同步进度 | 区分已保存、已准备、已同步和仍有待处理事项 |
| 执行绑定 | 已保存的 `task_chat_id`、`task_session_id` 等必要信息 |
| 必要运行状态 | 最近执行状态和时间、未读次数、结果摘要、暂停原因及必要错误信息 |
| 父子关联 | 子任务的来源关联等必要信息，不因查询扩展出其他用户的全部任务 |

返回定义和可变状态应明确分组，不能让客户端把运行状态误当作更新定义需要覆盖的字段。创建、更新、删除和同步进度的具体字段及状态枚举与对应写接口统一设计。

平台密钥、Provider 密钥、内部令牌和其他敏感配置不得直接返回；错误信息也需要脱敏。查询需要的执行配置不等于所有内部配置原样公开。

三态调度配置及平台切换进度已有独立 `GET /dispatch-state` 接口。详情中的必要摘要不替代该接口，也不能把定义版本和三态配置版本混为同一个未经定义的字段。

### 存在性及删除记录

| 数据库中的情况 | 行为 |
| --- | --- |
| 任务存在且未删除 | 返回当前定义及状态 |
| 任务已逻辑删除且记录仍保留 | 按权限返回删除标记和清理进度，不当作正常可更新任务 |
| 任务从未存在 | 返回 `404`，不读取文件兜底 |
| 任务已按独立保留策略物理清理 | 不伪造删除记录，具体历史可见性和错误契约另定 |
| 身份或权限不符合 | 拒绝操作，不泄露其他工作区的任务 |
| 数据库查询失败 | 返回明确错误，不伪造不存在、空定义或成功状态 |

读取已删除记录不表示允许恢复或更新任务，也不重新创建已清理的 Chat 或定时器。

### 内部流程

1. 解析任务身份和可信调用上下文，校验读取权限。
2. 根据完整身份查询 `swe_cron_jobs_v2`，读取对应 `swe_cron_job_states`。
3. 根据记录的真实状态组装定义、版本、进度、执行绑定和运行状态。
4. 脱敏后返回结果，不调用 SWE 或外部平台，不写任务表、旧表或文件。

读取以数据库持久化状态为准，不因为没有实时远程核验而自行修复，也不将一个缺失的状态字段默认成“已完成”。详情的一致性读取方式在实现时明确，避免定义和状态拼接出矛盾版本。

## 关联子任务查询接口

### 入参

```text
GET /api/scheduler/cron/jobs/{job_id}/broadcast/children
    ?scope_id=<源任务工作区>&agent_id=<源任务Agent>
```

`job_id` 是源任务 ID，scope 和 Agent 用于确认源任务，不是将全部子任务强行限定为同一个目标工作区。

补充查询参数的目标方案：

| 参数 | 用途 |
| --- | --- |
| `tenant_ids` | 可选目标 tenant 过滤，支持智拓按现有分发对象选择任务 |
| `include_deleted` | 默认不包含已删除子任务；显式开启时用于复核删除记录及清理进度 |
| `limit` | 每页数量，有服务端上限，具体默认值和上限待定 |
| `cursor` | 继续读取下一页，具体游标格式及排序规则待定 |

过滤字段的最终名称和多值传递方式待契约细化。过滤范围是授权源任务的关联子任务，不是任意 tenant 的任务列表。

### 返回内容

每个子任务返回必要的轻量字段：

- 子任务 ID、目标 tenant、source、scope、Agent 及名称。
- 定义版本、启用和删除状态。
- Cron、时区和实际散列偏移。
- 必要的执行准备、平台同步及删除清理进度。

默认不携带每个子任务完整执行正文或所有内部配置，需要详情时用该子任务自己的身份调用详情接口。

分页响应示例：

```json
{
  "source_job_id": "source-job-001",
  "items": [
    {
      "job_id": "child-job-001",
      "tenant_id": "sap1001",
      "source_id": "zhituo",
      "scope_id": "目标工作区身份",
      "agent_id": "default",
      "name": "场景任务",
      "definition_version": 3,
      "enabled": true,
      "deleted": false,
      "cron": "0 9 * * *",
      "timezone": "Asia/Shanghai",
      "offset_minutes": 0,
      "preparation_status": "completed",
      "platform_sync_status": "completed"
    }
  ],
  "next_cursor": null
}
```

示例 ID、字段名称和状态值不是实际数据库记录或最终枚举。`next_cursor` 非空表示还有下一页；为空表示在本次分页契约下已读完，不代表未来不会新增子任务。

智拓需要处理全部选定对象时，必须完整遍历分页。不能只删除第一页后就认为全部子任务已经处理，也不能将查询失败当作“没有子任务”。

### 内部流程

1. 校验源任务的完整身份和读取权限。
2. 根据源任务数据库身份和父子关系查询关联子任务，不只匹配一个裸 `job_id`。
3. 在数据库查询中应用目标过滤、删除过滤和分页，使用关系索引，不扫描用户目录或初始化各接收方 Workspace。
4. 合并必要状态并脱敏，返回当前页及继续读取标识。

源任务记录仍保留时，查询需与详情接口的删除可见性规则协调，避免因为源任务逻辑删除就掩盖需要复核的子任务；确切授权和历史可见规则在实现前细化。

查询不执行删除、不自动级联、不重新广播、不修改三态。智拓取得列表后，仍按原业务范围逐个调用单任务删除接口。

已确认权限范围：有权管理源任务的调用方可管理其关联子任务并查询整体分发结果；接收方仅能查询和管理自己的子任务，不能查询或操作其他接收方或源任务。沿用可信 Header 和既有授权体系，不因持有源任务或子任务 ID 获得额外权限，也不另建角色体系。

## 数据来源及只读约束

| 数据 | 来源 |
| --- | --- |
| 任务身份、定义、版本和父子关系 | `swe_cron_jobs_v2` |
| 执行绑定、运行状态及处理进度 | `swe_cron_job_states`；Scheduler 写管理字段，SWE 写实际运行字段 |
| 旧表投影 | `swe_cron_jobs` 仍承担其他兼容读取，本次两个新接口不以它作为新任务权威来源或缺失兜底 |
| 旧文件及内存 | 新任务不补写也不读取，不因缺失改变任务存在性判断 |

不新增查询专用表，不建立依赖文件仓库的任务缓存。查询不通过 Monitor 或 SWE HTTP 再复制同一份共用数据库数据。

详情直接读取 SWE 已提交到共库的实际运行状态，不要求 SWE 回传后由 Scheduler 再保存一份。任务运行状态与 Scheduler 的队列、批次进度分别表达，不能将“已派发”或“已接收”显示成“执行成功”。写入归属和一致性约束见 [执行状态写入分工](2026-10-14-zhituo-scheduler-cron-execution-entry-flow.md#执行状态写入分工与并发约束)。

新任务从 Scheduler 数据库接口查询，不为旧 SWE 查询补写文件或 `_states`，也不增加旧查询逐次查库回填。Chat 前端分别请求旧、新任务后按旧在前、新在后合并；会话有效性过滤也使用完整的新旧任务来源，接口失败或新列表未读完时不能把遗漏任务当作已删除。存量查询保持原逻辑。取消范围见 [文件与内存兼容取消说明](2026-10-15-zhituo-swe-cron-memory-compatibility.md)。

## 前端列表和标记已读配套能力

原有详情与子任务查询仍保持只读。新增的 Scheduler 任务列表供“定时任务（新）”页及 Chat 使用，只返回当前授权范围内由 Scheduler 管理的任务；需提供管理归属、完整身份、绑定和必要展示状态，排除仅导入的 legacy 快照。

标记已读是独立写操作，不混入查询副作用：旧任务沿用 SWE 旧接口；新任务由 Scheduler 新接口更新共库已读状态。Chat 打开任务、报告预览等入口使用相同归属分流规则。接口失败不得自动改用另一条写路径，且不能因标记已读覆盖 SWE 并发执行新产生的未读事实。具体字段与事务在实现前细化。

报告预览指任务执行产物的展示，不是迁移报告；保留原内容读取和预览，仅适配携带 CRON_JOB_ID 时的任务身份及标记已读调用。普通无任务关联的附件不因此切换接口。

新管理页还需查询“已删除、清理未完成”的记录及进度，供授权用户人工重试清理；不能以默认排除已删除任务为由隐藏所有续办入口。这类记录不是有效可执行任务，不应回到 Chat 正常任务列表，也不允许编辑、恢复或立即执行。最终清理完成后的历史可见性及保留期另行细化。

新页还需支持对子任务选中项批量删除、批量立即执行，优先组合复用单任务管理接口并展示逐项结果；查询接口本身仍不产生这些副作用。刷新列表直接重新读取数据库，不增加旧式扫描全部用户文件的刷新操作。优先级配置的读取、保存与新批次生效语义属于管理策略，不由详情查询隐式修复。

## 实现前需要细化的内容

- 精确响应模型及状态枚举，与创建、更新、删除和分发接口保持一致。
- 详情中的敏感字段和错误脱敏规则，创建人、管理者、接收人的读取范围。
- 定义、状态的一致性读取方式，以及部分准备或清理状态尚未保存时的表达。
- 父子关系的具体列、索引和目标多值过滤方式。
- 分页默认值、上限、稳定排序、游标及并发创建删除时的一致性规则。
- 已删除源任务、子任务及最终物理清理后的历史可见性。
- 智拓分页选择和逐个删除的调用方式，不扩展原业务删除范围。
