# 定时执行凭据数据库镜像设计

状态：已实现并通过规格与代码审查。业务取舍见 [ADR 0043](../../adr/0043-cron-auth-file-authoritative-database-mirror.md)，操作步骤见[运维文档](../../deploy/cron-auth-database-mirror.md)。最终受影响回归 539 项通过；尚未进行真实 MySQL 验收或部署。本阶段不切换业务读取。

## 已确认边界

- 新增数据库表，镜像 `cron_auth.json` 的完整状态，包括新增、修改、字段清空与显式删除。
- 顶层状态按字段分别存列；`user_info` 保留完整对象，序列化为 JSON 文本存入 LONGTEXT。
- 文件继续作为业务读取依据；数据库同步失败不改变已成功的文件操作结果。
- 不加锁，不保证并发写入顺序或自动最终一致，允许过渡期差异。
- 不增加自动重试队列、周期对账或自动修复。回填、核对、数据库多余记录清理由运维主动发起。
- 提供内部 HTTP 工具，一次提交后后台自动分批执行，通过任务 ID 查询进度；中断后可重新提交，不做跨实例自动接管。
- 核对发现数据库有记录而文件不存在时仅报告，由运维确认后显式清理。普通回填不删除数据库多余记录。
- 读取切换留给后续阶段；过渡时间到期不触发自动切换。

## 当前代码事实

`src/swe/app/crons/auth_state.py` 中，`save_cron_auth_state()` 集中保存普通状态，`cleanup_cron_auth_except_source()` 单独执行文件删除。写入来源包括配置 Cookie、更新用户信息、签发 Token、预取、任务执行时刷新，以及 HTTP 和 CLI 的刷新操作。一次预取可能保存多次，每次持久化均纳入镜像范围。

现有删除入口是 `POST /auth/cron-auth/cleanup`。它支持保留来源、强制删除租户和 dry-run，实际删除作用域根目录下的 `.secret/cron_auth.json`，不是删除任务或 Agent 配置。

读取还包括 `routers/system_check.py`、`skill_readiness/strategies.py`、`cli/auth_cmd.py` 的直接文件访问。本阶段保留这些读取及其既有缺失、无效文件判断语义。

## 表与身份映射建议

新增 `swe_cron_auth_states`，每个实际凭据文件作用域一行，保存当前快照，不增加历史版本表。

| 字段 | 用途 |
| --- | --- |
| `storage_scope_id` | 从本次实际文件路径对应的作用域根目录取得，唯一且区分大小写 |
| `tenant_id`、`source_id` | 可可靠识别时保存的身份信息，用于运维筛选；无法识别时保留空值，不猜测 |
| `user_info` | 完整用户信息对象，序列化为 JSON 文本存入 LONGTEXT，无需依赖原生 JSON 类型或 JSON 路径查询 |
| `user_info_expires_at`、`user_info_refreshed_at` | 用户信息有效期与刷新时间 |
| `auth_token`、`auth_token_expires_at` | Token 及其有效期 |
| `cookie_header` | 完整 Cookie |
| `last_prefetch_at`、`last_error` | 最近预取与错误状态 |
| `created_at`、`updated_at` | 数据库行创建及最后同步时间，不用于判定跨实例操作先后 |

数据库键从和文件保存相同的一次路径解析结果取得，不仅按逻辑 tenant 或 Agent 建键，也不重新拼接 tenant/source 来替换实际作用域。现有默认目录、`default_<source>` 与显式编码作用域可能对应不同文件；工具须保留这种区别。普通租户与来源不得因数据库默认的不区分大小写排序规则而合并。

每次写入完整快照，明确更新可空字段；不能因为文件序列化省略 `None` 而保留数据库中的旧 Token 或旧错误。日期按统一 UTC 语义转换，核对时比较规范化值，不比较 JSON 字符串顺序或数据库同步时间。

`user_info` 的模型是 `dict[str, Any]`，仓库中的鉴权工具是部署时替换的占位实现，没有固定的生产字段契约。用户最终确认沿用完整对象序列化方案，保留未知字段、嵌套对象及列表，不展开为固定业务列，也无需补充生产字段样例。回填与核对需验证对象序列化、反序列化后的语义一致性，避免改变未来 Token 签发所需的完整内容。

交付手工建表 SQL，应用不自动执行 DDL。目标表缺失或结构不兼容时，业务写入仍遵循文件成功优先；运维工具明确报告不可用。

## 双写流程建议

1. 解析本次文件路径和对应作用域身份。
2. 执行既有文件操作；文件失败则保留原有失败语义，不写数据库。
3. 文件成功后，在当前操作内尝试完整快照 upsert 或硬删除，设置有界等待。
4. 数据库成功则结束；数据库失败则记录作用域、操作类型和安全错误码，保留原操作成功结果。

dry-run 不删除文件，也不修改数据库。正常清理在文件删除成功后尝试删除对应数据库行；文件原本缺失的情形不隐式扩展为批量数据库清理，数据库多余记录由专用运维操作处理。

不增加锁、版本竞争协议或失败补偿队列。并发保存、删除、回填可能互相覆盖，数据库行也可能暂时复现已删状态；这些差异由运维核对和重跑修复。重复回填通过唯一键避免重复建行，不代表在线并发下保持某个历史快照。

现有保存和 Token 更新调用链是同步函数，现有 `DatabaseConnection` 是异步接口。建议将有关持久化调用链改为 async，由 HTTP、Cron 预取与执行、Workflow、Shell 调用方等待完成；同步文件与外部请求工作放入工作线程，避免阻塞事件循环。Workflow 的同步 secret loader 需要支持等待；Shell 凭据解析需接入异步准备边界，同时覆盖前台命令和后台进程启动。服务使用已有应用数据库连接；CLI 使用一次独立异步生命周期连接、执行并关闭。不在事件循环中嵌套 `asyncio.run()`，不采用无法在返回前确认结果的后台投递。

## 运维工具建议

使用独立的 `/api/internal/cron/auth-migration` 路径，避免和现有任务定义快照迁移混淆。建议提供：

- `POST /tasks`：接收操作与筛选范围，返回 HTTP 202 和 `task_id`。
- `GET /tasks/{task_id}`：读取任务状态、累计计数及分页诊断，不触发额外业务操作。

复用 `swe_async_tasks` 与 `swe_async_task_items` 保存进度，使用独立任务类型；这些既有进度表不可用时拒绝提交任务。已有任务快照迁移的 Runner 与 Store 含任务定义专用计数和类型，不能直接作为凭据迁移实例使用；优先复用通用异步任务写入能力，分页执行与核对采用本工具自己的逻辑。复用现有内部迁移接口的登录与已配置内部凭据校验，不新增匿名访问白名单。

| 操作 | 行为 |
| --- | --- |
| `preview` | 只读比较，列出预计新增、更新与数据库多余记录 |
| `import` | 从当前可读取文件完整 upsert，可重复执行，不删除多余记录 |
| `verify` | 同时扫描选定范围的文件和数据库，报告缺失、差异、多余、文件无效和读取失败 |
| `prune` | 运维显式提供范围后，重新检查当前文件，删除仍然缺失的数据库记录 |

支持租户、来源及实际作用域筛选；不能识别逻辑身份的兼容目录在结果中明确列出，允许按实际作用域精确操作。`prune` 必须显式指定范围，不将省略筛选解释为清理全库。目录不可访问或扫描失败不能解释成“文件不存在”；该范围停止清理并报告错误。无锁下重检不能消除所有并发窗口，不承诺原子清理。

扫描只覆盖执行实例实际可见的存储，不宣称一次扫描取得集群一致快照。工具不启动 Workspace，不签发或刷新凭据，不把数据库数据写回文件。数据库不可用时任务失败，不假报完成；局部错误保留逐项诊断，其余可处理记录继续处理。

诊断只返回身份、结果类型、差异字段名与安全错误码；Token、Cookie、user_info 内容不进入响应、任务进度或错误日志。异常 JSON 不按空状态回填，也不据此删除数据库记录。

## 验收与后续切换

实现阶段验证：完整快照及清空字段、来源和默认目录隔离、所有写入触发点、删除及 dry-run、数据库失败不影响文件成功、重复回填不重复建行、核对双向差异、显式清理范围、异步进度和重跑行为。保留现有文件读取测试，不测试或宣称无锁操作有严格顺序保证。

运维先执行建表、小范围预览与回填，再主动发起全量核对、修复差异。后续若准备切库，由运维安排最终核对及必要的写入静默窗口；在线核对完成只表示已检查观察到的数据，不能保证之后没有新差异。本阶段不实现读取切换、自动切换条件或自动回退。
