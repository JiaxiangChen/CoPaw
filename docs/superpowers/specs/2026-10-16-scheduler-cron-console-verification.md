# 新版定时任务 Console 验证记录与联调清单

## 入口与边界

旧页 `/cron-jobs` 不切换 API；新页 `/scheduler-cron-jobs` 只访问 `/api/scheduler/cron/jobs` 下的新管理接口。技能、时区和模型选项沿用现有只读资源查询。网关必须将新路径转发 Scheduler，不能因为请求失败回退 SWE 旧写接口。本地 Vite 当前通用 `/api` 代理指向 SWE，浏览器截图使用模拟响应；真实开发联调需使用已配置 Scheduler 路由的网关。

页面复用原表格、CSS Modules 和表单主体，新增管理状态、独立调度方式和包含已删除选项。新建任务 ID 由服务端分配；内容编辑不修改启停。旧页面两个共享组件新增可选参数，默认行为不变。

## 逐项验证

| 操作 | 检查点 |
| --- | --- |
| 列表 | 任务超过 200 条时完整遍历所有游标；数据库失败显示错误，不当作空列表或已删除；不展示 legacy 导入快照。 |
| 创建 | 三种任务类型使用新 POST；保存前确认 Header 的真实用户、目标 workspace 和 Agent；发送 request_id，不发送表单占位 ID 或只读管理状态。 |
| 更新 | 先读取新详情，以当前 definition_version 提交；存在子任务的源内容编辑由服务端拒绝；启停字段不可借内容 PUT 修改。 |
| 启停 | 使用 management_version；自动暂停同时按 task.is_paused 展示；恢复完成才根据实际查询更新状态，不把已读当恢复。 |
| 执行 | 显示 execution_id 和真实 queued/accepted/running/终态，排队不伪造成运行中；停用或运行中按钮禁用，服务端仍校验。 |
| 删除 | 可对已启用任务逻辑删除；在途执行继续，未开始工作跳过。勾选包含已删除后可查清理操作并续办。 |
| 分发 | 独立分发窗口，选择 0、1、1000 个目标；0 人仅散列，1001 人不能提交。请求没有批调度开关；返回任务 ID 后只查询结果。 |
| 分发进度 | 打开时查 current，再按 task_id 遍历结果所有页；未完成只查询，已终止可显式开启新一轮；分发失败在新轮处理。 |
| 调度三态 | 普通、开启批调度、暂停批调度；显示目标、实际混合状态和逐项计数。未完成或失败不得换目标，外部失败支持原操作重试。 |
| 优先级 | 原样式编辑用户/分行顺序，新保存接口携带 management_version；只影响新批次，不重排既有队列。 |
| 子任务 | 父任务授权入口完整分页，跨租户操作保留 X-User-Id；启停、详情、编辑、进度按目标 tenant/source/Agent 定位。批量执行/删除 1～1000 项，逐项展示结果。 |
| 批量删除续办 | 保存原 request_id 和原 items；网络中断或清理未完成时重试原请求，已成功项不重复创建或再删，结束整批后才开始新的选择。 |
| 切换身份 | 打开弹窗后切 Agent/source/用户或角色，旧工作区卸载，迟到查询不覆盖新数据，旧删除确认框不能继续提交。 |
| 失败 | 新 API 400/403/404/409/503 明确报错，不探测旧写接口；请求结果未知先保持原内容重试或查询进度，不另开创建请求。 |

## Chat 与报告补充验证

1. 同一个用户/source/Agent 下准备一旧一新两条任务，核对任务栏旧在前、新在后。两者即使 ID 相同也应保持不同选中态和动作归属；裸 taskId 链接若歧义则提示，不静默选旧任务。
2. 旧任务动作继续走 SWE；新任务编辑、启停、删除、执行与已读均走 Scheduler。新接口故意返回错误时，不得出现旧写请求。新执行受理后只显示真实进度，不能在本地伪造 running。
3. 分别令新旧列表失败：另一来源继续更新，失败来源已知任务保留。任务会话首页、后续分页均使用两份完整清单；某来源失败时不能按该来源的“空列表”删除会话。
4. 打开编辑/删除确认框或执行请求后切换 Agent/source/用户/角色，旧响应不能覆盖新列表、关闭新工作区的表单或继续提交旧确认。切走期间请求结束后切回来，仍应能发起新刷新。
5. 在任务 Chat 内打开报告，来源已明确时直接调用相应标读接口；独立报告只有 CRON_JOB_ID 时，先只读确认完整身份及来源。双边都存在或任一边查询异常时不试写，不标读；展示内容本身不阻塞。
6. 报告数据尚未真正渲染、正在切报告、预览关闭或身份改变时不标读旧响应；已读失败保留未读，重新打开可重试，不隐式恢复暂停。下载结果不能覆盖当前展示任务的来源。

浏览器已实际验证双来源布局与新任务停止路径，模拟请求仅发到新 enabled/operations 路径，旧任务不变。截图：`output/playwright/cron-chat-dual-source.png`、`cron-chat-new-task-control.png`。

本轮组合回归为 171 passed、5 failed（176 项）。两项 Blob 失败已通过 HEAD 原组件副本对照确认相同结果；三项未修改的点击追踪测试单独重跑也失败。它们与上一轮原页批标签断言、旧子任务过滤超时分别记录，不称为全仓库绿灯；未放宽检查或改旧断言。新增来源、会话身份、动作及报告分流的定向检查通过；另含切走再切回的旧响应围栏回归。
