# 定时任务第一阶段快照迁移设计

日期：2026-10-15。基线：`v1.0.0`。状态：代码已实现，本地验证结果见实施记录；未执行业务库迁移，真实 MySQL 集成验证待提供隔离环境。

## 目标与阶段边界

第一阶段只提供可重复、人工触发的快照导入，将现有任务定义和实际可取得的运行状态保存到 `swe_cron_jobs_v2`、`swe_cron_job_states`。只入库，不切换管理归属、前端查询或执行路径，不增加日常双写。

准备阶段的建表由操作者执行；本功能不包含建表 SQL、自动建表或启动时迁移。第二阶段的 Scheduler/SWE 新管理和执行能力、第三阶段的智拓对接均不在本次实现中。

已确认：允许内存状态部分缺失；文件定义全量扫描，内存只采集当前实例已经加载的部分，缺失项明确报告，之后可按用户路由补迁。不能为了采集状态初始化 Workspace 或启动 CronManager。

已确认：独立系统任务暂不迁移，包括心跳、梦境及 source 级清理、归档等。它们的系统配置、`system_jobs.json`、系统平台绑定和运行状态不属于此次采集来源，不为其合成新表记录。保存在用户 `jobs.json` 中的自动生成业务任务仍在范围内，不能只凭创建方式或 `job_origin=system` 将其排除。

## 数据来源与目标

| 数据 | 来源 | 目标及边界 |
| --- | --- | --- |
| 完整任务定义 | 既有用户 Workspace 的 `jobs.json` | 定义表 `spec_json` 及必要检索列；保留原任务 ID、模型、技能、Workflow、dispatch、runtime 和源子关联 |
| 聊天、会话及平台绑定 | 文件 meta 和可取得的本机状态 | 状态表；普通定时器与批入口分列，冲突不猜测覆盖 |
| 未读、结果摘要及暂停原因 | 文件 meta | 状态表中有证据的字段，缺字段不当作显式清零 |
| 最近运行状态、时间、错误、预取等 | 当前实例已加载 CronManager 中实际存在的状态项 | 状态表的运行快照；不能用 `get_state()` 返回的默认空对象冒充实际状态 |
| 批入口暂停状态 | 共库旧控制表中可确认的记录，可选只读 | 可确认时映射三态；缺表、缺记录或身份不完整则标记未知，不调用调度平台或修复旧表 |

不迁移执行历史，不写 `swe_cron_jobs`、`swe_cron_executions`、注册日志、执行登记或分发表，不调用 Monitor/Scheduler 同步接口。旧控制表不是新增依赖，缺失不阻断定义迁移。

定义中的 tenant/source 均有值时直接使用，不为取得这两个字段再解码 scope；缺少时才从已有 scope/存储目录按现有规则解析。来源互相矛盾、缺失或超长时报告冲突，不截断或冒用调用人的 Header 作为所有用户身份。

完整身份为 tenant、source、Agent、原 job ID。迁入记录保持 `management_owner=legacy`；管理阶段标为导入，而不是伪造 `ready` 或平台注册完成。

## HTTP 能力

建议新增以下 SWE 内部运维接口，最终以实现和 OpenAPI 为准：

| 方法与路径 | 作用 | 数据修改 |
| --- | --- | --- |
| `POST /api/internal/cron/migration/preview` | 分批预检来源、目标结构、身份及预计导入结果 | 只读 |
| `POST /api/internal/cron/migration/import` | 分批导入定义和可恢复状态 | 只写两张新表 |
| `POST /api/internal/cron/migration/verify` | 分批对照来源与数据库，返回缺失及差异 | 只读，不修复 |
| `POST /api/internal/cron/migration/tasks` | 一次提交预检/导入/核对，后台自动消费全部分页 | 导入只改两张业务表；三种操作均保存运维进度 |
| `GET /api/internal/cron/migration/tasks/{task_id}` | 查询累计进度和分页诊断，可跨实例 | 只读 |
| `POST /api/internal/cron/migration/tasks/{task_id}/stop` | 请求在当前批次结束后停止 | 只改进度状态，不撤销已提交业务数据 |

请求支持 tenant/source/Agent/job ID 过滤、小批量上限及继续游标。默认扫描当前服务可见工作目录内的用户 Workspace，范围跨所有 source；“全量”不表示跨实例内存已齐全，也不表示服务能读取其他实例不共享的文件系统。

游标记录相对来源键及任务位置、过滤条件指纹、文件清单指纹和必要文件指纹，不接受任意绝对路径，不作为权限凭据。以稳定来源键继续，不使用容易随目录增删偏移的纯序号。同步接口仍支持客户端逐页调用；推荐异步入口在收到请求的实例后台自动继续到结束，客户端不再传游标。

异步入口复用既有 `swe_async_tasks` 和 `swe_async_task_items` 保存累计结果、逐页安全诊断和心跳，不新增表或改列；这两张既有进度表缺失时明确返回 503，原同步能力仍只要求两张业务目标表。异步预检与核对会保存运维进度，但不修改业务数据。实例每 15 秒写心跳，超 120 秒未更新视为疑似中断；300 秒单页超时、最多两个本进程任务限制请求工作量。单页业务提交和进度提交不是同一事务，进度可能短暂落后；逐页诊断和汇总写入使用同一进度事务。

后台不承诺重启续跑或其他实例自动接管；停止请求在批次边界生效，已入库部分不回滚。异常后重新提交同范围全量扫描，沿用安全重跑保护。业务表与逐页日志不保存全部原始内容到进度 JSON；汇总只存计数，诊断逐页保存。核对缺失、差异和来源丢失会产生 partial_failed，不仅依赖底层单页的 partial_failure。内存缺失单列，不假称集群全量状态已经齐全。

预检与实际导入分别从第一页开始。预检是当时观察，不是锁住旧系统的承诺；来源改变后，导入重新校验。分页中途文件清单、当前文件或过滤条件变化时应明确拒绝旧游标，不能悄悄跳过记录。重跑同一页必须安全；拒绝后可从第一页重跑，不撤销前面已成功导入的数据。

响应包含本次操作、实例标识、过滤范围、扫描和处理数量、插入/更新/未变/冲突/失败/内存缺失计数、逐项安全诊断及下一页游标。诊断只返回业务身份、相对来源位置、缺失字段和差异字段名，不返回完整执行内容、Cookie、Token 或原始数据库异常。

定义成功但内存缺失单独表达，不能汇总成“状态全量迁移完成”。单条错误允许同页其他合法任务继续处理；基础设施不可用则返回明确不可用，不伪装成零任务。

## 扫描与采集安全

1. 根目录取服务已有工作目录配置，不接受请求指定文件系统根。
2. 按既有用户工作区和 Agent 布局枚举任务文件，兼容可识别的旧布局；不依赖必须有完整 config 才发现 jobs 文件。
3. 跳过已识别的全局/来源模板、隐藏备份、临时文件及非用户目录，不任意递归整个磁盘。无法识别布局时报告，不自动迁移目录。
4. 目录及文件必须解析后仍位于允许根内；拒绝符号链接逃逸和伪造游标路径。读取配置只解析副本，不调用会修复文件的配置加载函数。
5. 文件读取和解析放到已有运行状态工作线程能力，设置文件大小、单页记录和扫描工作量边界；异常 JSON 按文件报告，合法文件中的坏任务按条报告。
6. 复制实际存在的本机 `_states` 项，不创建或修改 manager、Chat、session、内存缓存或预取任务。采集不等于恢复执行。

文件和内存只保证各自观察时点的快照，不宣称两者与数据库存在统一事务。迁移期间发生旧任务修改或执行完成，可通过下一次快照补齐。

## 映射与缺失语义

- 明确区分“字段没有来源”和“来源显式给出零、空字符串或 false”。前者不覆盖已有值，后者在满足版本及归属规则后可更新。
- 新状态行可用数据库默认值初始化，但缺失运行状态保持未知，不能生成成功历史、当前执行身份或虚假的 running_count。
- 历史 `running` 只作为观察值并记录状态来源/观察时间，不证明现在仍运行，不触发补跑、取消或恢复。
- 原始排程优先使用已保存的 `broadcast_original_cron` 等证据。无法确认散列前原始排程时保留原定义并报告未知，不反复叠加偏移或计算平台定时器。
- 源子关联仅保存可确认的各维身份。只知道父 job ID 时不猜测父租户或 Agent，也不凭裸 ID 建唯一关系。
- 普通和批平台绑定各取对应来源；相互冲突时报告并保留可靠已有值，不调用平台注册来“修复”。
- 新表时间统一 UTC；只转换来源带明确时区的值。无时区而语义不明的历史时间单独报告，不按服务器时区猜测。
- 保留完整业务定义，去除明确的凭据字段及认证 Header；调用身份从业务归属恢复，不复制认证 Cookie/Token。脱敏策略要有针对性测试，不能把普通业务字段如 max_tokens 一并删除。

为识别重复来源和安全重跑，可在 `spec_json` 顶层保留迁移专用、非执行字段 `_snapshot_migration`，只包含来源相对键、内容指纹及快照观察信息，不污染原 meta、不增加列。后续生成执行定义时排除该辅助字段。源定义若已占用该保留字段则报告冲突。

## 重复导入与并发规则

| 目标情况 | 行为 |
| --- | --- |
| 完整身份不存在 | 在同一数据库事务中插入定义及初始状态 |
| 有定义但缺状态，且定义确由本迁移器持有 | 校验来源、归属及删除状态后补入初始状态，不重建任务身份 |
| 定义不存在但已有状态 | 报告孤立目标冲突，不把未知状态挂到新导入定义上 |
| 由本迁移器导入、仍属 legacy、未删除，来源相同 | 根据新快照更新有来源且较新的字段，相同业务内容跳过重复更新 |
| Scheduler 已接管，或管理/运行字段已经属于新路径 | 跳过并报告，不能将管理归属改回 legacy |
| 目标已逻辑删除 | 不恢复，不清除删除标记 |
| 同一完整身份来自不同文件且内容冲突 | 报告冲突，不用后来的文件覆盖先前来源 |
| 快照缺少内存状态或某字段 | 保留数据库已有值，报告缺失 |
| 快照比已保存的来源版本/观察顺序旧 | 跳过过期更新，报告原因 |

只允许更新本迁移器拥有的导入快照。已有行缺乏可信迁移来源标记时，不按 legacy 默认值直接覆盖。不提供 force 覆盖或删除重建参数。

单任务写入以同一连接的事务保证两表原子性，结合完整身份、行锁/版本条件处理竞争；初次并发插入、死锁或锁等待只做有上限的重试，不把所有数据库异常当重复键吞掉。失败回滚该任务，不出现有定义但迁移状态半写的成功报告。

快照更新时间与定义文件版本共同参与过期判断；零版本、相同版本但内容变化的旧文件仍需识别，不能只比较 definition_version。已存在的运行来源为实际执行时，不允许文件 meta 或缺失内存覆盖它。

数据库中有、当前文件中没有的任务仅在核对结果中提示，不据此自动删除或停用；缺少文件也可能是扫描范围、共享存储或并发变化问题。

## 权限和部署前提

迁移是跨用户运维操作，放在既有 internal 路径，不能作为普通用户管理能力宣传。沿用全局登录中间件及已配置的内部认证校验，不新增免登录白名单，不要求新增配置或新的 Token。

登录启用时照常提供登录认证；如现有 `SWE_INTERNAL_TOKEN` 已配置，按现有约定提供内部认证 Header。两种凭据并存时分别校验，不能用登录 JWT 误当内部密钥。

未配置应用认证时，安全边界是现有可信内网/网关隔离；用户信息 Header 只用于路由和身份上下文，不是全量迁移授权。运维部署必须限制这些内部路径，不能直接公开到普通前端网关。接口正文不能自行扩大为任意文件系统操作。

## 验收与回退

- 同步能力只要求两张目标表；异步全量额外要求已有异步进度两表可用，缺表/列明确失败，不自动 DDL。
- 独立系统任务及其配置、平台绑定、状态不导入；普通用户任务、分发子任务等不因自动生成而漏迁。
- 预检、导入、核对均可通过 Postman 一次提交后查询结果，也保留手动分页；过滤全部 source 时不漏其他来源的用户定义。
- 同一输入重复导入不重复建任务；旧定义改变后手工重跑能更新同来源 legacy 快照。
- 部分状态缺失或后来按用户路由补迁，不重置已保存的运行信息。
- scheduler 归属、删除标记、较新状态及不同来源冲突均受保护。
- 执行前后原 `jobs.json` 内容/时间戳、原内存、旧表以及平台接口调用次数均不因迁移改变；不启动新 Workspace。
- 错误、游标篡改、文件改变、符号链接、敏感字段及并发插入都有针对性测试。
- 回退是停止调用迁移接口/回退应用，保留导入数据；无自动 DROP、旧表回写或平台撤销操作。
