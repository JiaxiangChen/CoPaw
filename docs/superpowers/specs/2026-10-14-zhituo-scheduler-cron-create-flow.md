# 智拓经 Scheduler 创建定时任务流程

日期：2026-10-14

开发基线：`v1.0.0`

状态：管理核心及 SWE 资源准备已实现，完整新执行链路仍在开发；实际接口与限制见[管理接口开发记录](2026-10-16-scheduler-cron-management-api.md)。

修订：2026-10-15，按[第二阶段最新边界](2026-10-15-zhituo-scheduler-cron-phase2-boundaries.md)取消文件、旧内存投影；Scheduler 新任务的普通与批调度均使用新版入口。

智拓作为独立应用，通过 Scheduler 接口创建定时任务。Scheduler 负责任务管理、创建阶段的数据库写入和外部调度平台注册；SWE 负责执行资源准备，不为新任务补写 `jobs.json` 或 SWE 旧内存投影。实际执行阶段的运行状态由 SWE 直接写入共用数据库，创建准备接口不承担该写入。数据库是新任务的权威数据源，新任务的执行和查询均不依赖文件或旧内存。

本次先打通智拓这一条新建任务路径，不立即切换其他定时任务入口，也不直接合入此前迁移 worktree 的全部实现。删除、修改、广播和执行接口的详细流程后续分别梳理。

## 三个应用的职责

| 应用 | 负责 | 不负责 |
| --- | --- | --- |
| 智拓 | 管理规划、场景、分发对象及发布状态；组装任务请求；保存 Scheduler 返回的任务 ID | 不直接调用 SWE 内部函数，不自行注册调度平台，不承担新任务定义和状态的维护 |
| Scheduler | 校验创建请求、确认任务归属、幂等处理、生成任务 ID、保存任务定义、初始化状态及保存创建管理进度、调用 SWE 准备接口、注册外部平台、返回创建结果 | 不创建 SWE 的 Chat，不通过 `jobs.json` 获取新任务定义，不代写 SWE 实际执行产生的运行结果 |
| SWE | 定位执行环境、校验依赖 SWE 的配置、创建或复用 Chat 和会话绑定、补全执行参数；后续执行时直接持久化运行状态，不补写文件或旧内存 | 创建准备接口不写任务定义及状态表，不为新任务注册平台，不调用旧创建流程写任务文件并同步 Monitor |

SWE、Monitor、Scheduler 连接同一个数据库。智拓维护规划数据，Scheduler 维护任务数据，SWE 维护执行资源；不需要通过服务间 HTTP 再复制同一份任务数据库数据。

`swe_cron_job_states` 按业务动作和字段分工，不限定整张表只能由一个服务写：Scheduler 在创建时初始化记录及必要的运行字段，后续只维护管理字段；SWE 在执行时更新运行字段。共同的并发约束见 [执行状态写入分工](2026-10-14-zhituo-scheduler-cron-execution-entry-flow.md#执行状态写入分工与并发约束)。

## 创建流程

创建接口同步等待必要的资源准备、平台同步和数据库最终提交后返回结果，不采用“先返回 202、后台完成创建”的主流程。异常或请求超时保留已保存的任务和操作进度；再次请求复用同次操作，不把未收到响应当作尚未创建。失败后由用户人工续办，不新增自动后台业务续办；2026-10-17确认没有平台注册查询接口，无已保存ID按注册失败处理，原操作人工重试允许再次新增并接受可能遗留重复定时器的风险；已保存ID则复用。分发及实际执行的异步边界不因此改变。

### 1 智拓保存规划并提交创建请求

智拓先保存自己的规划、场景等数据，再为场景向 Scheduler 提交任务创建请求。请求需要携带任务名称、任务类型、执行内容、技能、Cron 和时区、执行对象及相关身份、规划和场景的业务关联，以及稳定的创建请求标识。

创建请求标识用于防止超时或后台发布重试产生重复任务。相同标识和相同内容应返回同一任务及当前进度；相同标识对应不同内容时应报告冲突，不静默覆盖。

Scheduler 将规划和场景关联视为通用业务关联，不接管财富规划业务规则。智拓不再 import 或直接调用 `CronManager`、`broadcast_job()` 等 SWE 内部能力。

### 2 Scheduler 校验请求并保存待准备任务

Scheduler 校验调用权限、tenant、source、scope、Agent 和执行用户的合法归属，以及任务类型、内容、排程、时区、超时和并发参数。确认请求没有重复创建后，由 Scheduler 生成任务 ID。

在一个数据库事务中写入：

- `swe_cron_jobs_v2`：任务定义、归属、业务关联和定义版本。
- `swe_cron_job_states`：初始任务状态及创建进度，任务尚不可执行。

先保存任务和创建进度，再调用 SWE 和外部平台。中途失败后，重试继续处理同一个任务，不重新分配任务 ID。

创建进度状态的名称和字段尚待细化；“待准备”“准备失败”“注册失败”“已就绪”等表示阶段含义，不是已确定的数据库枚举。

### 3 Scheduler 调用 SWE 执行准备接口

Scheduler 向 SWE 传递已生成的任务 ID、已确认的身份上下文及任务执行参数。SWE 的准备接口完成以下工作：

1. 定位对应 Workspace 和 Agent，检查执行上下文是否可用。
2. Agent 任务显式指定模型时，检查对应执行环境的 Provider 和模型配置；Workflow 任务解析 source、技能对应的启用配置绑定；文本任务不需要模型和 Workflow 配置准备。
3. 根据任务 ID、用户及会话归属创建或复用任务 Chat 和稳定的会话绑定。
4. 设置任务名称及 Chat 的任务归属元数据，补全执行请求和需要绑定的输出路由。
5. 返回任务 ID、Chat ID、会话 ID、Workflow 绑定标识、补全后的执行参数，以及明确的准备结果或失败原因。

准备接口应按同一任务身份幂等复用资源，不重复创建 Chat。配置检查不是提前执行 Agent 或 Workflow，也不保证外部服务在未来执行时一定可用。

此阶段不写新任务的 `jobs.json` 内容，不注册调度平台，不写新任务定义和状态表，也不调用 Monitor 的旧任务同步接口。当前 SWE 的 Chat 资源仍涉及 `chats.json`；本次不是全部 SWE 文件存储迁移。

执行准备必须从旧创建逻辑中独立抽取，不能整体调用 `create_or_replace_job()`，也不能依赖 `_ensure_task_binding()` 中读取 `jobs.json` 旧 metadata 的逻辑。

### 4 Scheduler 保存执行准备结果

SWE 准备成功后，Scheduler 更新任务定义和状态：

- 更新 `swe_cron_jobs_v2` 中补全后的执行参数、Workflow 绑定等定义内容。
- 更新 `swe_cron_job_states` 中的 Chat、会话绑定和准备进度。
- 由 Scheduler 在首次创建时初始化未读次数、是否已有执行结果等任务状态；重试不能重置 SWE 已写入的执行结果或未读状态。

这时任务已经具备 SWE 执行条件，但还没有完成外部调度平台注册。

### 5 Scheduler 注册外部调度平台

Scheduler 在 `swe_cron_registration_journal` 记录平台注册请求及调用进度，再调用平台。取得外部调度 ID 后，保存到注册日志和 `swe_cron_job_states`，并根据任务期望状态设置平台启停。

新任务的平台回调入口指向 Scheduler。后续触发由 Scheduler 从数据库取得任务执行定义并调用 SWE，不再让 SWE 根据任务 ID 查询 `jobs.json`。

调度 ID 应及时持久化，回调入口必须检查任务是否就绪，避免平台提前触发尚未准备完成的任务。平台注册、启动与数据库就绪状态之间的具体控制顺序，需要结合平台接口能力细化。

任务调度类型不能混淆：普通任务和批父任务可以有对应的物理定时器；批子任务不注册独立定时器。广播及批模式的详细处理不包含在本次单任务创建流程中。

### 6 Scheduler 完成数据库创建及旧表兼容

必要步骤成功后，Scheduler 在数据库事务中将 `swe_cron_job_states` 标记为创建完成，并将最终任务定义和绑定信息写入 `swe_cron_jobs` 兼容投影。

旧表投影用于保留现有 Monitor、智拓相关查询对新任务的可见性。Scheduler 为新任务写投影，不修改 SWE、Monitor 原有旧任务写入逻辑，也不绕回 Monitor 的 HTTP 同步接口。

创建完成不等于任务必须启用：用户创建的暂停任务也可以完成创建，外部平台保持暂停即可。

### 7 Scheduler 返回结果并由智拓保存关联

Scheduler 返回任务 ID、创建进度、执行准备和平台注册结果，以及必要的绑定信息。只有数据库和必要创建步骤完成，才能返回创建完成；不能把“已保存任务”表示成“已具备调度条件”。

智拓保存场景与任务 ID 的关联，更新自己的发布状态。本流程不投递文件或旧内存兼容写入。

如果需要分发给其他客户经理，智拓后续调用单独的 Scheduler 广播接口。单任务创建接口不负责保存整个财富规划、选择分发对象或执行整套广播流程。

## 写表及资源准备顺序

| 阶段 | 写入方 | 写入对象和内容 |
| --- | --- | --- |
| 保存规划 | 智拓 | 自己的规划、场景和分发对象数据 |
| 确认创建请求 | Scheduler | `swe_cron_jobs_v2` 保存初始定义；`swe_cron_job_states` 保存初始状态和进度 |
| 准备执行资源 | SWE | 自己的 Chat 资源；当前仍涉及 `chats.json` |
| 收到准备结果 | Scheduler | 更新 `swe_cron_jobs_v2` 和 `swe_cron_job_states` |
| 调用调度平台前后 | Scheduler | 写 `swe_cron_registration_journal`，更新 `swe_cron_job_states` 的注册状态和外部 ID |
| 数据库创建完成 | Scheduler | 更新创建完成状态；写 `swe_cron_jobs` 兼容投影 |
| 收到创建响应 | 智拓 | 保存场景对应的任务 ID，更新发布状态 |

状态表名称确定使用 `swe_cron_job_states`，不加 `v2`。任务定义表、注册日志和旧表兼容投影采用当前讨论的表方案；当前 `v1.0.0` 尚未接入此前 worktree 的 v2 管理逻辑。不能认为原有表结构已具备本流程全部字段。

## 兼容和失败处理边界

Scheduler 创建的任务及分发子任务归新路径管理，不写 `jobs.json` 或 `_states` 兼容投影。普通任务注册到 Scheduler 新普通入口，批父任务注册到新批入口。旧入口不得接管新任务；其他存量任务保持原路径，第一阶段快照导入不改变管理归属。

| 情况 | 处理边界 |
| --- | --- |
| 重复提交同一创建请求 | 返回并继续同一个任务，不重新创建 |
| SWE 准备失败 | 保留创建进度和错误，任务不可执行；重试复用同一任务身份 |
| 平台注册失败或返回结果不明 | 保留注册日志和状态，不把任务宣告为创建完成；无已保存ID时原操作人工重试可以再次新增，可能重复；已保存ID不重建 |
| 数据库最终写入失败 | 不返回创建完成；已经产生的外部副作用需要凭保存的进度恢复，不能假设跨系统自动回滚 |

数据库、SWE 执行资源和外部平台之间没有统一事务。创建进度和幂等标识用于恢复，不包含文件或旧内存兼容操作。

## 实现前需要细化的内容

- Scheduler 创建接口和 SWE 准备接口的具体路径、鉴权、请求和响应字段。
- 创建请求幂等标识的存储位置、唯一约束及请求内容冲突判定。
- `swe_cron_job_states` 的字段及创建进度状态；相关建表和升级 SQL。
- `swe_cron_jobs` 兼容投影的具体字段和事务边界。
- 平台未保存ID按失败重试可能留下重复定时器的风险，以及启用与任务就绪之间的控制顺序。
- Scheduler 管理标记和旧 SWE 补注册、回调跳过新任务的具体识别办法。

以上是实现细节的待办，不改变已经确定的服务职责、数据库权威性及新旧路径隔离。
