# 智拓经 Scheduler 更新定时任务流程

日期：2026-10-14

开发基线：`v1.0.0`

状态：更新流程已梳理，尚未实现

关联设计：

- [智拓经 Scheduler 创建定时任务流程](2026-10-14-zhituo-scheduler-cron-create-flow.md)
- [智拓经 Scheduler 删除定时任务流程](2026-10-14-zhituo-scheduler-cron-delete-flow.md)

Scheduler 提供独立的更新接口。更新和创建共用大部分内部处理能力，包括参数校验、SWE 执行准备、数据库保存、平台同步和兼容文件写入；更新保留既有任务身份、资源绑定和运行状态，不借用创建接口重新生成任务。

本次处理智拓通过新流程创建的任务，不需要存量智拓任务兼容或 `jobs.json` 查询兜底。数据库仍是权威数据源，SWE 异步维护文件兼容副本。

## 接口和业务范围

创建和更新采用两个独立入口：

```text
POST /api/scheduler/cron/jobs
PUT  /api/scheduler/cron/jobs/{job_id}
```

以上为目标接口形式，具体请求、响应和鉴权契约需要在实现前细化。

智拓修改规划时：

- 保留的场景沿用原任务 ID，调用更新接口。
- 新增场景调用创建接口。
- 移除场景调用删除接口。
- 分发子任务的创建或更新仍由单独的广播流程处理，不由源任务更新接口自动级联执行。

Scheduler 一次更新指定的一个任务，不修改财富规划数据，不扫描或更新其他用户的全部任务。跨租户、跨工作区或任务所有者变更不隐含在普通更新请求中。

## 三个应用的职责

| 应用 | 负责 | 不负责 |
| --- | --- | --- |
| 智拓 | 保留规划修改业务规则；提交保留场景的新任务定义和原任务 ID；处理返回结果；按原发布流程发起广播 | 不直接调用 SWE 的 `create_or_replace_job()`，不自行修改平台定时器 |
| Scheduler | 读取既有任务、校验权限和版本、记录更新进度、保存定义、保留运行状态、调用 SWE 准备、更新已有平台定时器、维护旧表投影 | 不新分配任务 ID，不因普通更新自动广播，不重置任务运行状态 |
| SWE | 按需校验执行配置；复用并更新既有 Chat、会话及执行路由；异步更新文件和内存兼容副本 | 更新准备接口不写新任务定义和状态表，不重复注册平台，不调用 Monitor 的旧同步接口；实际执行写运行状态不受此限制 |

SWE、Monitor、Scheduler 使用同一个数据库。更新流程的定义、准备绑定和管理进度由 Scheduler 写入，SWE 准备接口返回准备结果；实际执行的运行状态由 SWE 直接写入同一张 `swe_cron_job_states`，不再 HTTP 同步一份相同的运行状态。

## 创建和更新的差异

| 项目 | 创建 | 更新 |
| --- | --- | --- |
| 任务 ID | Scheduler 生成新 ID | 使用原 ID |
| 任务存在性 | 创建新任务 | 必须找到存在且未删除的任务 |
| 重试 | 同一次创建请求不得重复建任务 | 同一次更新应可识别，不重复产生副作用 |
| 版本 | 建立初始定义版本 | 校验原定义版本，成功写入新版本 |
| Chat 和会话 | 创建或复用稳定资源 | 保留并复用既有绑定，按需更新名称和执行参数 |
| 外部平台 | 注册对应定时器 | 更新原定时器，不重复注册 |
| 运行状态 | 初始化 | 保留，只更新与定义及同步进度有关的状态 |
| 兼容文件 | 按 ID 插入或更新 | 按原 ID 更新，无记录时可以补入兼容副本 |

创建请求的幂等语义不等于允许不同内容覆盖已有任务。更新既有任务必须走更新入口，不将“更新目标不存在”静默转为创建。

## 必须保留的身份和状态

更新时保留：

- 任务 ID、工作区和 Agent 归属、创建人及已有资源归属。
- `task_chat_id`、`task_session_id`。
- 已有普通及批父任务的外部调度 ID。
- 未读次数、最近执行结果和摘要、最近执行时间、已有执行历史。
- 手动或自动暂停相关状态，不因为客户端省略字段或模型默认值而恢复任务。

明确要求修改启用状态时，按新定义处理，并与既有暂停状态协调；具体字段优先级待契约设计时确定。不能用更新请求中的默认值或旧状态快照整体覆盖 `swe_cron_job_states`。

正在执行的任务状态可能同时发生变化。定义更新应只修改本次负责的字段，避免覆盖并发执行回写、已读或自动暂停操作。

Scheduler 不代写执行成功、失败等运行结果，SWE 的执行收尾也不得覆盖 Scheduler 的定义、平台绑定、调度模式或删除状态。使用字段级更新及执行身份校验，不整行覆盖，见 [执行状态写入分工](2026-10-14-zhituo-scheduler-cron-execution-entry-flow.md#执行状态写入分工与并发约束)。

## 更新流程

### 1 智拓提交原任务 ID 和新定义

智拓针对保留场景使用原任务 ID，提交新名称、排程、执行内容、技能及其他允许修改的定义字段，并携带用于并发校验的原定义版本。

客户端不通过更新接口提交新的任务 ID、外部调度 ID 或任意 Chat ID 来替换数据库绑定。同一次更新重试的识别方式、请求标识和内容冲突规则待接口契约细化。

### 2 Scheduler 读取任务并校验

Scheduler 根据任务 ID、scope、Agent 从数据库读取当前任务，校验调用权限及任务归属，并检查定义版本。

| 情况 | 行为 |
| --- | --- |
| 任务存在、未删除、版本符合 | 继续更新 |
| 任务不存在 | 返回 `404`，不创建新任务，不查询文件兜底 |
| 任务已经删除 | 拒绝更新，不恢复任务 |
| 定义版本不符合 | 返回版本冲突，不能覆盖其他修改 |
| 身份或权限不符合 | 拒绝操作，不修改数据 |

已删除和版本冲突的具体响应契约待确定；版本冲突采用明确的冲突响应，而不是最后一次请求无条件覆盖。

### 3 校验新定义并记录更新进度

Scheduler 复用创建接口中的任务定义校验能力，检查新内容、任务类型、技能、Cron、时区、超时和并发参数等。

校验通过后记录本次更新进度，保留用于重试和版本确认的信息，不重新初始化任务状态。

新定义的暂存方式、更新期间是否仍按旧定义执行，以及何时切换为生效定义，需要在实现前细化。不能直接把尚未准备完成的执行配置当作可执行版本。

### 4 按需调用 SWE 执行准备接口

涉及名称、执行参数、模型或 Workflow 配置等变化时，Scheduler 将任务 ID、现有资源绑定和新执行参数交给 SWE。仅修改无需 SWE 准备的字段时，可以复用已有准备结果。

SWE 按需完成：

- 定位原工作区和 Agent，校验执行上下文。
- 校验指定模型配置，或解析更新后的 Workflow 配置绑定。
- 核对并复用原 Chat 和会话，更新任务名称及必要元数据。
- 补全执行请求和需要绑定的输出路由，返回准备结果。

不因为普通更新每次创建新的 Chat、会话。绑定缺失或资源失效时的修复办法需单独明确，不能静默把更新变成另一份任务创建。

SWE 准备接口不读写新任务的 `jobs.json` 内容，不注册平台，不写任务表。不得整体调用旧 `CronManager.create_or_replace_job()` 或依赖文件中的旧 metadata。

### 5 Scheduler 保存定义和准备结果

Scheduler 在版本校验下保存补全后的定义，更新 `swe_cron_jobs_v2` 的定义版本，并按需更新 `swe_cron_job_states` 的准备、绑定或同步进度。

定义版本校验不能只在请求开始时执行一次。最终保存也要确认没有其他更新或删除抢先完成；跨服务准备结果晚到时不得覆盖新版本或恢复已删除任务。

此次保存不是用一份旧的完整状态快照覆盖状态表，未读次数、执行结果等仍以数据库最新值为准。

### 6 Scheduler 更新原平台定时器

Scheduler 使用原有外部调度 ID 更新平台上的任务名称、Cron 等信息，并根据明确的启停要求协调状态。回调入口仍指向 Scheduler，不改回 SWE 旧回调。

按任务类型处理：

- 普通任务更新自己的普通定时器。
- 批父任务按允许修改的定义更新属于自己的批定时器；批模式启停的其他语义另行梳理。
- 批子任务没有独立定时器时，跳过独立平台更新。

不因为普通更新重新注册一份定时器。需要物理定时器却缺失绑定的异常如何修复，需要显式定义，不能暗中走创建分支。

平台更新请求及结果需要保存进度。可复用创建流程的外部操作日志能力，具体对 `swe_cron_registration_journal` 的扩展待细化。

### 7 Scheduler 保存最终同步结果及旧表投影

必要步骤完成后，Scheduler 保存当前版本的准备、平台同步结果，更新 `swe_cron_jobs` 兼容投影。定义、状态和投影的一致性应由数据库事务及版本校验保证，不经 Monitor HTTP 接口同步。

更新完成不表示任务必须启用。原本暂停的任务不能因为一般内容更新被默认恢复。

Scheduler 返回任务 ID、定义版本及更新进度。数据库保存成功和平台同步完成应明确区分，不能将未完成的平台同步表示为全部更新完成。

### 8 SWE 异步更新 jobs.json 兼容副本

数据库及必要同步完成后，Scheduler 将最新完整任务交给 SWE，通过与创建流程共用的 `LegacyJobsFileWriter` 更新兼容文件：

- 定位原 scope、Agent 下的文件。
- 按原任务 ID 更新，保留其他任务；文件或记录缺失不改变数据库中任务存在的事实，可以补入兼容副本。
- 兼容内容根据最新数据库定义及必要状态组装，不能将更新请求中的默认未读次数、空摘要等覆盖已有状态。
- 使用文件锁，不等待写完，不回读校验。
- 文件投递或写入失败记录日志，不将已完成的数据库更新判成失败。

文件操作仍携带 Scheduler 管理标记。旧 SWE 补注册和回调路径不能重新接管该任务。

更新后的已提交状态也尽力刷新 SWE 内存兼容投影，保留既有运行结果，不通过默认值重置状态。它与文件写入分别封装、分别可移除，见 [内存兼容方案](2026-10-15-zhituo-swe-cron-memory-compatibility.md)。

## 写表和文件的顺序

| 阶段 | 处理方 | 对象和操作 |
| --- | --- | --- |
| 校验及登记更新 | Scheduler | 读取定义和状态，校验原版本，保存必要的更新进度 |
| 准备执行资源 | SWE | 按需复用和更新已有 Chat、会话及执行配置 |
| 保存定义和准备结果 | Scheduler | 更新 `swe_cron_jobs_v2`；只更新 `swe_cron_job_states` 中本次负责的字段 |
| 更新平台 | Scheduler | 使用原调度 ID 更新平台，保存外部操作及同步进度 |
| 完成更新 | Scheduler | 保存当前版本的最终同步结果，更新 `swe_cron_jobs` 兼容投影 |
| 更新文件兼容副本 | SWE | 异步按原任务 ID 更新 `jobs.json`，不等待、不回读 |
| 返回后处理业务结果 | 智拓 | 处理规划更新结果，按原发布流程另行发起广播 |

状态表继续使用 `swe_cron_job_states`，不加 `v2`。本次不重复建任务状态记录，不清理已有运行结果或历史。

## 失败及并发边界

| 情况 | 处理边界 |
| --- | --- |
| 任务不存在或已经删除 | 拒绝更新，不自动创建或恢复 |
| 定义版本冲突 | 不覆盖新版本，返回冲突 |
| SWE 准备失败 | 不重新分配任务或资源 ID；记录未完成进度，具体生效版本和重试规则待细化 |
| 平台更新失败或结果不明 | 保存进度和错误，重试仍使用原外部 ID，不注册重复定时器 |
| 数据库保存失败 | 不宣告全部更新完成，保留可恢复信息；不能假设 SWE 或平台副作用自动回滚 |
| jobs.json 写入失败 | 只影响兼容副本，不影响已完成的数据库更新 |
| 更新同时收到执行结果、已读或自动暂停 | 不以旧快照覆盖这些状态 |
| 旧更新或旧文件请求晚到 | 不覆盖较新定义，不恢复已删除任务 |

新版本生效、平台注册同步和文件写入不在一个跨系统事务中。文件模块需结合最新定义版本、删除状态和锁处理过期操作；删除标记优先于晚到的更新结果。

## 复用创建逻辑的方式

创建和更新使用独立 HTTP 入口，共用内部能力。公共逻辑包括任务参数校验、SWE 准备调用、定义保存、平台请求及日志、旧表投影和兼容文件投递。

创建分支负责分配身份和初始化；更新分支负责读取既有身份、校验版本、保留状态、更新既有资源。不能通过让智拓重发创建请求来模拟更新，也不能以复用内部函数为由混淆两个接口的对外语义。

## 实现前需要细化的内容

- 更新请求和响应字段、原定义版本的传递方式、同一次更新重试的识别方式。
- `PUT` 中可修改、必填和只读字段，以及省略字段和默认值的处理。
- 任务类型变更、启停要求及已有暂停原因之间的规则。
- 更新期间旧定义是否继续执行，新定义的暂存、生效和失败恢复顺序。
- 哪些字段变化需要调用 SWE，以及准备结果与 Chat 元数据更新的版本控制。
- 已有资源或平台绑定缺失时的显式修复边界。
- 外部操作日志扩展、旧表投影事务及异步文件请求的版本识别。
- 已启动执行在定义更新后使用何种快照；本次不预先确定取消或重启策略。
